# Astrbot万能工具箱

AstrBot 肥鱼工具组：鲸言四字符编解码、鲸绘图片混淆，以及可调用已有 TTS 的语音后处理提供商。支持 OneBot v11、QQ 官方 WebSocket / Webhook，通过宿主标准消息接口兼容更多平台。

需要 AstrBot >=4.29.3,<5。鲸言、鲸绘只由指令启动，各有独立开关。TTS 后处理通过提供商调用，不新增聊天指令或 LLM 工具。

运行依赖：复用宿主 Pillow、aiohttp 和 NumPy；新增 **PyWORLD 0.3.5**（WORLD 的 Python 接口），音频处理需要已安装的 **FFmpeg**。在 AstrBot 的 Python 环境安装本插件 `requirements.txt`，兼容的现有 NumPy 无需升级。不需要 GPU 或下载语音模型。

## 鲸言

| 命令 | 作用 |
| --- | --- |
| `/鲸言` | 帮助与预设 |
| `/鲸言加密 你好` | 默认“嗡呜隆嗷”字表 |
| `/鲸言解密 密文` | 从完整密文首尾恢复字表 |
| `/鲸言加密 我是肥鱼 你好` | 自定义四字符有序字表 |
| `/鲸言解密 我是肥鱼 密文` | 按指定字表校验并解码 |
| `/鲸言加密 兽音 你好` | 使用“兽音”预设 |
| `/鲸言解密 兽音 密文` | 使用“兽音”预设 |
| `/鲸言加密 -- hello world` | 默认字表下包含空格的正文 |

首项之后还有正文时，首项按参数解释：两个字符为预设名，四个互不重复的可见字符为字表；其他长度报错。只有一个文本项时就是正文。默认字表下的多词正文用 `--`，避免将正文首词当成参数。内部空格和换行保留，命令及正文两端的空白可能由宿主裁剪。

字符按 Unicode 码点计数，单码点 emoji 可用，组合 emoji 可能不止一个字符。不能使用重复、空白或控制字符。不支持五至八字符字表。

默认预设：兽音=嗷呜啊~，喵音=喵呜啊~。可在插件设置页面编辑，格式为 `两字名称=四字加密词`，保存并重载生效。自动解码不遍历预设，而是读取密文首尾字表；不支持缺失首尾的猜测恢复，不支持佛曰。

算法兼容所核对的[兽音格式](https://github.com/sgdrg15rdg/beast_js/blob/main/beast.js)，包括 UTF-16 代理对。此功能是趣味编码，不是保密加密；旧格式没有校验和，不能检测所有损坏。

肥鱼别名：`/肥鱼嘀咕`（加密）、`/肥鱼翻译`（解密）。

## 鲸绘

| 命令 | 作用 |
| --- | --- |
| `/鲸绘` | 帮助 |
| `/鲸绘加混 [图片]` | 加混一次 |
| `/鲸绘解混 [图片]` | 解混一次 |
| `/鲸绘加混 3 [图片]` | 加混三次 |
| `/鲸绘解混 3 [图片]` | 解混三次 |
| `/鲸绘解混 3` | 等待本人下一张图片 |
| `/鲸绘取消` | 取消等图，不中断已开始的处理 |

同条消息附图优先，图片在文字前后均可。未附图时默认等 **60 秒**；只领取同平台、同机器人、同会话、同用户的下一张图片。普通文字不会延时，其他用户的图不会被处理；重复图片命令替换旧等待。超时静默失效，需要重新发命令；重载清空等待。一次仅支持一张静态图片。

QQ 官方群聊若不投递普通图片消息，请 **@机器人并附图**。平台没有交给宿主的消息无法抓取。

算法为[小番茄图片混淆网站](https://xiaofanqiehunxiao.com/)的 Gilbert 曲线路径循环像素置换。多次变换合并计算，解混需使用相同次数。输出 **PNG**，不主动缩放、不重复 JPEG 压缩，保留解码后的 RGBA 像素。网站导出 JPEG，因此跨网站恢复不保证像素无损。平台转码、缩放、裁剪、图片旋转或错误次数会影响还原。

默认限制：20 MiB 输入/输出、800万像素、单边4000、最多10次、并发2、排队8。超限提示错误，不自动缩图。透明通道保留；EXIF 朝向在处理前规范化，不承诺保留原文件元数据。若平台有更严格的消息或附件限制，请在设置页调低预算。

肥鱼别名：`/肥鱼拌饭`（加混）、`/肥鱼摆盘`（解混）。

## TTS 后处理

1. 加载插件，在 AstrBot 的语音合成提供商页面新增 `omnikit_tts_postprocess`（万能工具箱 · TTS 后处理）。
2. `上游TTS实例ID` 填入已有且启用的 Edge TTS 或其他 TTS 实例 ID。上游负责声音、语言和鉴权。
3. 启用该提供商，将会话的 TTS 提供商选择为这个后处理实例。可创建多个实例，分别选择上游和效果。
4. `启用后处理` 填 `true` 或 `false`；关闭只透传上游声音。宿主的提供商启用开关则决定实例是否可用。插件总开关关闭时同样透传。

`音频预设` 默认 `GLaDOS`，也可填 `中性` 或已保存名称。参数留空表示继承预设，填写数字表示覆盖；保存提供商配置后生效。GLaDOS 是机器人音效预设，不是原角色音色克隆；效果取决于上游音色，中文建议保留一定语调起伏。

| 参数 | 范围 | GLaDOS 默认 |
| --- | --- | --- |
| 音高偏移（半音） | −12～12 | −1 |
| 目标基频（Hz，0保持） | 0 或 50～600；先设中心音高，再加半音偏移 | 0 |
| 语调起伏（倍） | 0～2；0 为平调，1 保留起伏 | 0.65 |
| 语调平滑（毫秒） | 0～80 | 15 |
| 共振峰（倍） | 0.7～1.4；改变音色共鸣位置 | 1.08 |
| 气声（倍） | 0～2；改变有声段非周期成分 | 0.8 |
| 频谱倾斜（dB每倍频程） | −6～6；正值提亮 | 0 |
| 金属感（0至1） | 0～1 | 0.12 |
| 金属调制频率（Hz） | 10～200 | 45 |
| 效果混合（0至1） | 0～1；WORLD 与原音混合比例 | 1 |
| 语速（倍） | 0.5～2；独立于音高 | 0.98 |
| 低频／高频增益（dB） | −12～12 | 0／2 |
| 输出增益（dB） | −18～12，最终限幅 | 0 |
| 基频检测下限／上限（Hz） | 50～200／200～1000，下限须小于上限 | 60／600 |
| 基频算法 | `harvest` 或 `dio` | `harvest` |

`效果混合=0` 仍会应用语速、均衡和输出增益；完全透传请关闭后处理。`FFmpeg路径` 默认 `ffmpeg`，不在 PATH 时填写可执行文件绝对路径，不要附加命令参数。

**保存预设：** 在 `保存预设名称` 填一个新名称并保存提供商配置，会保存当前实际生效的音频参数。该字段非空时，此实例每次保存或重载都会同步该预设；清空后停止同步。其他实例填同名 `音频预设` 即可使用，清空参数覆盖项可完整继承。已加载的实例需要重新保存配置才能读取预设更新。内置预设不能覆盖，同名自定义预设只允许创建它的实例更新。

自定义预设由 `StarTools.get_data_dir` 定位，存放于 `data/plugin_data/astrbot_plugin_omnikit/tts/presets/`，JSON 内含可读名称，文件名为名称哈希。最多 64 个；重启和插件代码更新不丢失。

处理链：上游音频 → FFmpeg 解码 → WORLD 调整 → 语速／均衡／限幅 → 24 kHz 单声道 PCM16 WAV → AstrBot 发送。仅处理选择了本提供商的 TTS 调用，支持实现宿主 `get_audio()` 并返回本地音频路径的上游。不会拦截直接调用其他提供商的结果。采用整段处理，不提供原生流式合成；平台最终语音编码由 AstrBot 适配器决定。

所有实例共享 1 个处理槽、4 个等待位；默认最长 60 秒音频、60 秒处理超时（含排队），提供商页面可调至 180／300 秒。输入上限 50 MiB，超限不截断发送，处理失败时回退原音频并记日志。提供商健康检查会直接报告处理失败；上游合成本身失败则交由 AstrBot 处理。CPU 与内存随音频时长增长，`dio` 可用于尝试降低处理延迟。

不修改或删除上游文件；中间文件由任务清理，输出保存在 AstrBot 临时目录供宿主管理。卸载插件前请把会话的 TTS 改回上游提供商。

## 开发与验证

`main.py` 管理注册和生命周期；`core/gateway.py` 负责指令与等图；`core/text.py`、`core/image.py`、`core/audio.py` 是算法；`core/tts.py` 管理预设和音频子进程；`core/adapter/` 封装 AstrBot 接口。运行时不访问算法参考网站。

所有运行文件采用 UTF-8 / CRLF。测试与兼容边界见 [docs/TESTING.md](docs/TESTING.md)，实现设计见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)，图片原理见 [docs/IMAGE_RESEARCH.md](docs/IMAGE_RESEARCH.md)。

当前已验证本地 AstrBot 4.29.3 的三协议消息结构和真实命令管线，发送端隔离模拟；**真实 QQ 账号联调与平台传图后的压缩行为尚未验证**。其他平台复用通用接口，尚未逐平台验收。
